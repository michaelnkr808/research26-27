## What the papers agree on (`verified` for each statement above; the pattern is `speculative`)

- The common SoundSpaces convention is a telephone ring or a set of category sounds, a source at the goal point at 1.5 m height, a binaural receiver at 1.5 m, and a window of about one second per step.
- Nobody reports mono as a separately rendered signal for navigation. NaVLA2 and Hear, Localize, and Reason build mono as a downmix of the binaural render. SoundSpaces 2.0 allows a separate mono microphone, but no paper found uses it for a mono baseline.
- A sound that stops exists only in SAVi's semantic setup; no paper found cuts the sound when the agent arrives.
- The default HRTF of SoundSpaces 2.0 is not named in its paper, its docs or the code read; Hear You Are calls it "the default Head Related Transfer Function provided by SoundSpaces2.0".

## Not found or not stated

- A source position given relative to an object's box rather than a point (centre against navmesh node): NaVLA2's paper says centre, its code uses an annotated `position` whose origin is not shown; SAVi says only "at the locations of the Matterport objects".
- The length of the telephone-ring clip, and the telephone file itself (the sounds are a separate download, not opened).
- The sample rate in SAVi.
- A paper-against-code mismatch in SoundSpaces 2.0: the paper says 0.15 m per step, the code uses 0.25 (`default.py:219`); not resolved.

Written by the planning lead from the five reviewed survey files in this folder. It adds no new sources. Every statement under "What exists" and "What was not found" points to the survey file that carries the entry, the quote and the link. Three things come from the direction's own records, not the survey files, and are marked where they appear: the lead's statements and the 200 dollar compute budget (`../../LOG.md`, `../../STANDARDS.md`), and what is known about the RMS-AQA baseline (`../../LOG.md` 2026-11-16). ## The idea, in the lead's words
"Add an audio encoder to the world action model so it can also make decisions based on audio input" (2026-11-16). The lead prefers Wan 2.2 as the base and leans toward navigation, not robot-arm manipulation, as the setting (2026-11-16, not yet a decision record).

## What exists

**World action models with an audio path, but no audio in control** (`verified`, file C).
- Cosmos 3 (NVIDIA, open weights): the base model takes and generates two-channel 48 kHz audio with video and actions. Its released robot policy takes cameras and proprioception only. Its audio came from web video, and the model card caps audio input at 0.5 s. Whether its two channels carry direction was not checked.
- FLUX 3 Action: audio in pretraining only.
- For the other world action models read, audio is future work or a gap the two 2026 surveys name.

**Navigation world action models built on Wan 2.2, none with audio** (`verified`, file D; the audio part is a keyword search of each paper's full text, not a code check).
- WNM-3D: navigation, Wan2.2-TI2V-5B, tested on GN-Bench (Gaussian-splat scenes) and VLN-CE R2R; code with training scripts for two of its three stages and checkpoints are released; the released weights are non-commercial research use; trained on 16 H100.
- AstraNav-World: navigation, Wan2.2-TI2V-5B with LoRA plus a vision-language planner, tested in Habitat; inference code and part of the weights released, no video-generator training script found; trained on 96 H20.
- UniWAM and ABot-M0.5: mobile manipulation (a base plus an arm) on Wan 2.2 5B. UniWAM releases training and inference code; its two released checkpoints are navigation-only (not the full mobile-manipulation model), and the data on Hugging Face is a subset.
- NavGen: drones, nothing released yet.
- Navigation world models on other bases include Wan 2.1, Cosmos Predict2, SVD, LTX-Video, LTX-2.3, InfinityStar and Anole-7B, and Navigation World Models, which trains from scratch (the full list is in file D's closing section).

**Models that predict audio; no world model among them is built on Wan 2.2** (`verified`, files C and D).
- Audio-Visual World Models (arXiv 2512.00883): predicts frames and binaural audio under navigation actions in SoundSpaces. A small model, not a pretrained video model. No code, weights or data release found. (`speculative`, planning lead: this is the closest paper to the direction.)
- HelixWorld and EchoWM: explorable generated worlds with sound, built on LTX-2.3, not robot policies.
- Ovi and MOVA: joint audio-video generators built on Wan 2.2 (MOVA's audio is mono). They are generators, not world models: no actions.

**Spatial audio does help an acting agent, where it was tested** (`verified`, file B).
- Simulated navigation: NaVLA2 (a vision-language-action model with binaural input) reports higher success with its binaural branch than with its mono-downmix branch. The two branches use different pretrained encoders, so the comparison is not only about channel count, and one run per row is reported.
- Real-robot manipulation: SoundAct (stereo, a workshop project page, ten trials per condition) and S2A2 (microphone arrays, a preprint). Small or not clean as spatial-versus-mono tests.
- Question answering: comparisons in BAT and JAEGER, not agent tasks. OmniEcho's main table compares a base model with a fine-tuned one, so it is not a controlled mono-versus-spatial test, and its navigation result has no mono variant.

**Reusable spatial audio encoders** (`verified`, file B; release status differs per entry).
- SpatialAST from BAT (the spatial branch NaVLA2 uses), SPUR, JAEGER, and OmniEcho's first-order Ambisonics encoder.
- Not from the survey files: the RMS-AQA baseline also has a trainable spatial branch for first-order Ambisonics (`../../LOG.md` 2026-11-16, read from the paper and code README, not run).

**Data** (`verified`, file E).
- No finished download in the NaVLA2 form was found: NaVLA2's MINav set and checkpoints are listed as unreleased in its repository, and no release was found for the Audio-Visual World Models data or LH-AVLN.
- What is public is the means to render such data: SoundSpaces 2.0 on Habitat (binaural or Ambisonics, on scene scans that have their own access terms), with released sound libraries and episode definitions from SoundSpaces and BeDAViN. File E's closing section lists what has to be obtained and run.
- Public real recordings: OmniEchoBench (first-order Ambisonics recorded at grid points in 30 scanned rooms, frames rendered from meshes, about 198 GB, license statement unclear), and smart-glasses recordings with a 7-microphone array and head trajectories but no navigation actions (Ego-Exo4D, Aria Everyday Activities), each behind a license agreement.
- No real-robot release with passive spatial audio, egocentric video and the robot's own actions was found.

## What was not found
Each of these is "not found in these searches", worded as narrowly as the reviews allow.
1. A world action model trained or evaluated with audio as an input to control, for manipulation or navigation.
2. A navigation world model built on Wan 2.2 (or any large pretrained video model) that takes or predicts audio.
3. A controlled spatial-versus-mono comparison for a world action model.
4. A ready dataset with egocentric video, spatial audio and navigation actions in a usable raw form.

## What this suggests for the direction (`speculative`, planning lead)
- The open space the lead's idea sits in: take a Wan 2.2 navigation world action model, give it spatial audio, and measure whether it navigates better, with a same-model no-audio baseline and a mono baseline. Items 1 to 3 above say that has not been published as far as these searches reach.
- Candidate bases under the lead's Wan 2.2 preference: WNM-3D (navigation, training code and checkpoints) looks the most usable; AstraNav-World and UniWAM are the alternatives. All were trained on large GPU counts (16 H100, 96 H20, 16 H200 per file D), far above the direction's 200 dollar budget (`../../STANDARDS.md`), so the realistic form is to start from a released checkpoint and train a small added part. Whether that fits the budget is unknown until someone times it.
- Data is the largest piece of work: a training set has to be rendered with SoundSpaces 2.0. Habitat is possible common ground: AstraNav-World is evaluated in Habitat (file D), and SoundSpaces 2.0 renders audio in Habitat (file E). For WNM-3D, file D names GN-Bench and VLN-CE R2R and does not say which simulator runs them, so whether WNM-3D's evaluation can run where SoundSpaces 2.0 renders audio has to be checked.
- RMS-AQA connects as a possible source of the spatial audio encoder (first-order Ambisonics in, direction-aware features out), and OmniEchoBench shares its audio format. This link is the planning lead's guess and should be confirmed with the PI.
- Risks to check before committing: the scene datasets' terms make rendered data non-commercial and probably not shareable; SoundSpaces is archived and pins old Habitat versions, which may not match the versions the navigation models use; the Audio-Visual World Models paper is the nearest prior work and has to be read closely for overlap.

## Open choices for the lead and the PI
- Setting: navigation in a simulator (the lead's lean) or something else.
- Base: which Wan 2.2 navigation world action model.
- Audio format and encoder: binaural or first-order Ambisonics, and which pretrained spatial encoder.
- What the Interspeech paper has to show (`../../README.md`, "What done looks like").
